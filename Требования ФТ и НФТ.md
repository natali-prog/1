# Требования к системе мониторинга и аналитики продаж

## 1. Функциональные требования

| ID | Название требования | Описание |
|---|---|---|
| FR-01 | Авторизация пользователей | Система должна предоставлять авторизованным пользователям доступ к функциям мониторинга и аналитики в соответствии с их ролью. |
| FR-02 | Просмотр данных о продажах | Система должна предоставлять возможность просмотра информации о продажах за выбранный период. |
| FR-03 | Фильтрация данных о продажах | Система должна предоставлять возможность фильтрации продаж по периоду, категории товара, товару, магазину и продавцу. |
| FR-04 | Анализ продаж по категориям | Система должна рассчитывать показатели продаж в разрезе категорий товаров: количество проданных единиц и сумму продаж. |
| FR-05 | Определение лидеров продаж | Система должна определять товары и категории с наибольшим объёмом продаж за выбранный период. |
| FR-06 | Просмотр информации о товарах | Система должна предоставлять информацию о товарах, включая категорию, наименование, цену и доступность товара. |
| FR-07 | Просмотр остатков | Система должна предоставлять информацию об остатках товаров по магазинам и складам. |
| FR-08 | Автоматический импорт данных поставщиков | Система должна автоматически получать и загружать данные от подключённых поставщиков о новых поступлениях и остатках товаров. |
| FR-09 | Периодическая синхронизация | Система должна автоматически запускать синхронизацию данных с поставщиками один раз в сутки в 23-00 UTC +3 (GMT +3). |
| FR-10 | Обработка новых поставок | Система должна сохранять информацию о новых поставках, включая поставщика, товар, количество и дату поступления. |
| FR-11 | Синхронизация остатков | Система должна обновлять информацию об остатках товаров на основании полученных от поставщиков данных. |
| FR-12 | Контроль дубликатов | Система должна выявлять повторно полученные записи поставщика и предотвращать их повторную обработку. |
| FR-13 | Обработка ошибок импорта | Система должна фиксировать ошибки обработки данных поставщика и сохранять информацию, необходимую для анализа и повторной обработки. |
| FR-14 | Мониторинг импорта | Система должна предоставлять информацию о статусе последней синхронизации с каждым поставщиком: выполняется, успешно завершена или завершена с ошибками. |
| FR-15 | Повторный запуск импорта | Система должна предоставлять пользователю с соответствующими правами возможность повторно запустить импорт, завершившийся с ошибкой. |
| FR-16 | Формирование аналитических отчётов | Система должна предоставлять агрегированные данные для построения аналитических отчётов в Apache Superset. |
| FR-17 | Экспорт отчётов | Система должна предоставлять возможность экспорта сформированных отчётов в форматы Excel и PDF. |
| FR-18 | Анализ динамики продаж | Система должна предоставлять возможность анализа динамики продаж за выбранный период. |
| FR-19 | Анализ продаж по магазинам | Система должна предоставлять возможность анализа и сравнения показателей продаж между магазинами. |
| FR-20 | Анализ ассортимента | Система должна предоставлять аналитические данные о спросе на товары для поддержки принятия решений по ассортименту. |

## 2. Нефункциональные требования

| ID | Название требования | Описание |
|---|---|---|
| NFR-01 | Производительность | Время обработки аналитических данных не должно превышать 1 минуты при штатной нагрузке. | (хорошо было бы промониторить среднюю нагрузку и пиковые)
| NFR-02 | Устойчивость к сбоям | Сбой при обработке данных одного поставщика не должен приводить к остановке обработки данных остальных поставщиков. |
| NFR-03 | Идемпотентность импорта | Повторная обработка одного и того же набора данных поставщика не должна приводить к созданию дублирующих бизнес-записей. | (с учетом ключа идемпотентности)
| NFR-04 | Аудит операций импорта | Система должна сохранять информацию о времени импорта, поставщике, результате обработки, количестве полученных, обработанных и ошибочных записей. |
| NFR-05 | Масштабируемость | Архитектура системы должна обеспечивать возможность подключения новых поставщиков без существенного изменения существующей функциональности. |

| NFR-08 | Целостность данных | Система должна обеспечивать целостность данных при загрузке информации от поставщиков и сохранении результатов обработки. |
| NFR-09 | Восстановление после сбоя | После восстановления системы должна существовать возможность продолжить обработку незавершённого импорта без потери ранее успешно обработанных данных. |
| NFR-10 | Контроль качества данных | Система должна валидировать обязательные поля импортируемых данных и отклонять записи, не соответствующие установленным правилам валидации. |
